# BMEDIA-MD — Render deployment

This build is prepared for a Render **Web Service**.

## What changed for Render

- Adds a lightweight HTTP server using Node's built-in `http` module.
- `GET /health` returns HTTP 200 for Render/UptimeRobot.
- Restores WhatsApp auth from the existing MongoDB `SESSION_ID` document.
- Continuously syncs updated Baileys credentials back to MongoDB.
- Removes the pairing service's short-lived `expireAt` field once the main bot claims the session, so the deployed bot can restore after later restarts.
- Persists runtime JSON state (`control/*.json`, `data/*.json`) and `assets/logo.png` in the same MongoDB session document.
- Uses a generated `commands/manifest.json` so commands remain lazy-loaded instead of importing the whole command directory at startup.
- `.env` is excluded from Git. Put real values in Render Environment Variables.

## Render service settings

- Service type: **Web Service**
- Runtime: **Node**
- Build command: `npm install`
- Start command: `npm start`
- Health check path: `/health`
- Instance: **Free** for testing

Do not set a fixed Render port unless necessary. The application listens on `process.env.PORT`, which Render supplies automatically.

## Required environment variables

Use the values from your current private `.env`. At minimum the deployed bot needs:

- `SESSION_ID`
- `MONGODB_URI`
- `SESSION_DB_NAME`
- `SESSION_COLLECTION`
- `PHONE_NUMBER` / `OWNER_NUMBER` as currently used by your bot
- your existing bot identity/config variables

The `SESSION_ID` must refer to a session generated by your BMEDIA-MASTER pairing service and stored in the same MongoDB database.

## UptimeRobot

After Render gives you a public domain, monitor:

`https://YOUR-RENDER-DOMAIN/health`

Use an HTTP(S) monitor at a 5-minute interval if available.
